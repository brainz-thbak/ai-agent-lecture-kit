# AI 에이전트 강의 키트

`ai-agent-study` 저장소의 같은 앱(`app`)에서 단순 세션과 스킬·피드백 루프의 결과를 비교하는 도구다.
에이전트가 정답을 보지 못하도록 이 저장소는 `ai-agent-study` 밖에 둔다.

| 파일 | 내용 |
| --- | --- |
| `task.md` | 에이전트에 입력할 과제 티켓(요구사항 13개)과 놓치기 쉬운 곳 |
| `fixtures.mjs` | 이전 보존 정리 과제의 seed 데이터. 첨부 교체 과제에서는 쓰지 않는다 |
| `reset.mjs` | 앱 DB 와 file-store 데이터 전체 초기화 |
| `seed.mjs` | 첨부 교체 과제 데이터를 API 로 입력 (교체 대상 A·B·C·E, 비교 대상 D) |
| `grade.mjs` | 이전 보존 정리 과제의 채점. 첨부 교체 과제 채점은 아직 없다 |
| `skills/` | 피드백 루프 조건에서만 설치하는 Codex 스킬 4개 (`orchestrate-feedback` 이 진입점) |

Node.js 24 이상에서 의존성 없이 실행한다.

## 진행 순서

아래에서 `STUDY` 는 `ai-agent-study` 저장소 경로다.

1. 서버를 모두 종료하고 초기화한다.

   ```sh
   node reset.mjs $STUDY
   ```

2. 단순 세션 조건을 실행한다. 조건마다 `main` 에서 브랜치를 새로 만들고, 서버 시작과 seed 부터 다시 한다.

   ```sh
   cd $STUDY && git switch -c run/session main
   pnpm dev                                # 다른 터미널에서 계속 실행
   node seed.mjs                           # 키트 저장소에서, 기본 http://localhost:8080
   ```

   **에이전트가 실행되는 동안 키트를 디스크에 두지 않는다.** 에이전트는 상위 폴더를 탐색해 `grade.mjs` 를 읽을 수 있다. seed 뒤에 키트 폴더를 지우고, 에이전트가 끝나면 다시 받는다.

   `$STUDY/app` 에서 에이전트를 띄우고 `task.md` 의 티켓을 입력한다. 에이전트가 질문하면 "티켓대로 진행해 주세요."라고만 답한다. 끝나면 키트를 다시 받아 서버가 켜진 상태에서 채점하고 결과를 브랜치에 커밋한다.

   ```sh
   git clone https://github.com/brainz-thbak/ai-agent-lecture-kit.git
   node grade.mjs                          # 기본 http://localhost:8080
   ```

3. 피드백 루프 조건을 실행한다. 서버를 끄고 reset 한 뒤 `main` 에서 새 브랜치를 만든다.

   ```sh
   node reset.mjs $STUDY
   cd $STUDY && git switch -c run/feedback main
   pnpm dev
   node seed.mjs
   mkdir -p $STUDY/app/.codex && cp -R skills $STUDY/app/.codex/   # 키트를 지우기 전에 스킬 설치
   ```

   같은 방식으로 진행하고, 티켓 앞에 `$orchestrate-feedback` 을 붙여 스킬을 호출한다. 스킬은 `$STUDY/app/.codex` 에만 설치한다. `~/.codex/skills` 처럼 전역 위치에 두면 단순 세션 조건에도 적용된다. 채점이 끝나면 `$STUDY/app/.codex` 를 지운다.

## 채점

`grade.mjs` 는 코드와 DB 를 보지 않고 API 응답만 확인한다. 티켓의 요구사항 중 API 로 확인할 수 있는 12개를 채점한다.

```text
자동 채점 요구사항 12개 중 9개 충족 · 12번은 화면에서 확인

  ✓  1. 336시간 지난 처리 완료 건만 정리
  ✗  6. 실행 중 재호출은 409
        동시 호출: 기대 200, 409, 실제 200, 200
  ✗ 10. 정리된 이벤트로 보고서 생성 거부
        INC-1004 로 보고서 생성: 기대 409, 실제 404
```

채점은 아래 순서로 상태를 바꿔 가며 진행한다. **seed 직후에 한 번만 실행한다.** 다시 채점하려면 reset 과 seed 부터 한다.

1. 정리 API 를 동시에 두 번 호출 (요구사항 6)
2. 건별 첨부·이벤트 조회, 보고서 다운로드, 파일 수 (1·2·3·4·5·11)
3. 정리 API 재실행 (5)
4. 정리된 INC-1004 에 법적 보존 설정, 같은 이벤트로 보고서 생성 (8·10)
5. INC-1001 법적 보존 설정·해제, 없는 이벤트에 설정 (7)
6. INC-1008 법적 보존 해제 후 정리 실행 (9)
7. 정리 이력 조회 (13)

- `✓` 충족, `✗` 미충족, `–` 판정 불가. 미충족이면 어떤 요청이 무엇을 반환했는지 세 줄까지 적는다.
- 정리된 첨부가 하나도 없으면 2번(법적 보존 제외)은 판정하지 않는다. 동시 호출이 둘 다 성공하면 실행이 겹치지 않았을 수 있어 6번도 판정하지 않는다.
- 기대 결과는 API 의 `closedAt`·`legalHold` 와 채점 시각으로 계산한다. 모두 충족하면 종료 코드 0 이다.
- `--detail` 을 붙이면 개별 검사를 모두 출력한다.
- 화면 요구사항과 파일 삭제 실패 후 재시도는 출력 끝의 "화면·수동 확인" 목록대로 직접 확인한다.

## 주의

- 티켓 밖의 정보는 주지 않는다. 두 조건이 같은 정보로 시작해야 빠뜨린 요구사항 수를 비교할 수 있다.
- **seed 와 채점은 같은 날 00:30~23:30(KST) 사이에 한다.** 정리 기능은 실제 현재 시각으로 판단하고, 경계 건(INC-1002, INC-1003)은 이 시간대에서만 기대 결과가 성립한다.
- seed 는 스키마 버전 3 인 빈 DB 에만 넣는다. 서버를 한 번 실행해 DB 가 만들어진 뒤, 에이전트를 실행하기 전에 seed 한다.
- 에이전트가 개발 중에 이벤트를 추가하거나 정리 API 를 미리 호출할 수 있다. 채점 전에 seed 데이터가 그대로인지 확인한다.
- `DEMO_DATA_DIR`, `FILE_STORE_URL`, `FILE_STORE_SPACE` 를 바꿔 서버를 실행했다면 seed 에도 같은 값을 준다. `reset.mjs` 는 기본 경로만 지운다.
