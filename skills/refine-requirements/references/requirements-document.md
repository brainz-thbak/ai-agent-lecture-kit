# 요구사항 문서 구조

| 항목 | 포함할 내용 |
| --- | --- |
| 목표와 범위 | 사용자가 얻는 결과, 변경 대상, 관련 동작 중 유지할 것 |
| 현재 동작과 근거 | 요청과 직접 관련된 관찰이나 코드 근거, 이미 합의된 제품 정책 |
| 상세 요구사항 | `REQ-01` 형식의 ID, 대상, 적용 조건, 기대 동작, 출처 |
| 수용 기준 | `AC-01` 형식의 ID, 요구사항 ID, 사전 조건, 동작, 관찰 가능한 기대 결과 |
| 가정과 미결 결정 | 영향을 받는 요구 또는 기준 ID, 선택에 따라 달라지는 결과, 요청자에게 물을 질문 |

작은 변경은 짧게 작성한다. 목표와 범위, 요구사항, 수용 기준은 직접 연결하고 나머지 항목은 판단에 필요할 때 추가한다.

## 작성 예시

요청은 “프로젝트 목록에서 보관된 프로젝트도 포함해서 볼 수 있게 해줘. 기본은 활성 프로젝트만 보여줘.”이고, 기존 목록에서 이름 검색이 동작하는 것을 확인한 경우다.

**목표와 범위**

기존 프로젝트 목록에서 보관된 프로젝트를 확인할 수 있다. 이름 검색은 선택한 목록 범위에 적용한다.

**상세 요구사항**

- `REQ-01` — 기본 목록은 활성 프로젝트만 표시한다. 사용자가 보관 포함을 선택하면 활성·보관 프로젝트를 함께 표시한다. 근거는 사용자 요청이다.
- `REQ-02` — 이름 검색을 사용하면 선택한 목록 범위 안에서 검색어와 일치하는 프로젝트를 표시한다. 근거는 기존 목록의 검색 동작이다.

| 기준 | 요구사항 | 사전 조건 | 동작 | 관찰 가능한 기대 결과 |
| --- | --- | --- | --- | --- |
| `AC-01` | `REQ-01` | 활성 프로젝트와 보관 프로젝트가 각각 있다. | 목록을 처음 연다. | 목록에 활성 프로젝트만 표시된다. |
| `AC-02` | `REQ-01` | 활성 프로젝트와 보관 프로젝트가 각각 있다. | 보관된 프로젝트를 포함하도록 선택한다. | 목록에 두 상태의 프로젝트가 모두 표시된다. |
| `AC-03` | `REQ-02` | 보관 포함 상태이며 검색어가 보관 프로젝트 한 건의 이름에만 일치한다. | 프로젝트 이름을 검색한다. | 일치하는 보관 프로젝트 한 건이 표시된다. |

**미결 결정**

`REQ-01`의 범위가 세션 중에만 적용되는지, 나중에 목록을 다시 열어도 유지되는지 요청에서 확정하기 어렵다면 기존 필터의 동작을 먼저 확인한다. 적용할 기존 규칙이 없으면 요청자에게 묻는다. 답변을 받은 뒤 목록을 다시 열었을 때의 수용 기준을 확정한다.

## 조건과 기대 결과가 섞인 요청

“만료된 초대 링크를 정리한다”는 요청을 받으면 만료 판정 시각, 경계에서의 비교, 정리 후 링크 조회나 사용 결과를 구분한다. 현재 시스템에 만료 시각이 이미 있으면 그 의미를 근거로 남긴다. 실행 주체와 초대 기록 삭제 여부가 정해지지 않았으면 요청자에게 확인한다. 답변을 받기 전까지 관련 기준은 미결 또는 조건부로 적는다. 만료 직전과 정확한 만료 시각은 별도의 사례로 검증할 수 있게 작성한다.
