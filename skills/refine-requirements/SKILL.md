# 요구사항 구체화

사용자 요청을 바탕으로 변경할 동작, 적용 범위, 근거, 수용 기준을 담은 상세 요구사항 문서를 작성한다.

## 요청자 확인 원칙

**결정이 필요한 사안은 절대 임의로 확정하지 않는다. 반드시 요청자에게 질문하고 명시적인 답변을 받는다.**

- 요청이나 합의된 정책만으로 기대 동작을 정할 수 없거나, 근거가 서로 충돌하면 미결로 기록한다. 질문에는 선택지마다 달라지는 결과와 영향을 받는 요구사항 또는 수용 기준을 포함한다.
- 요청자가 답하기 전까지 해당 결정과 그에 의존하는 요구사항·수용 기준은 미결로 둔다. 응답이 없더라도 기본값이나 권장안을 확정한 것으로 처리하지 않는다. 미결 결정과 독립적으로 확정할 수 있는 부분은 계속 작성한다.

## 입력과 근거 확인

1. 사용자 요청에서 목표, 대상, 바꿀 동작을 한 문장으로 정리한다. 이미 내려진 결정, 기존 문서, 검토 의견은 제공된 경우 함께 사용한다.
2. 관련 자료나 코드에 접근할 수 있으면 요청을 해석하는 데 필요한 만큼 실제 진입점과 현재 동작을 확인한다. 사용자에게 보이는 동작, 관련 데이터, 기존 제약 중 요구사항 판단에 영향을 주는 내용만 적는다. 근거는 문서 제목이나 파일 경로와 심볼로 남긴다. 코드로 확인한 사실과 실행으로 관찰한 결과를 구분하고, 자료가 없어서 확인하지 못한 내용은 미확인으로 표시한다.
3. 얻은 정보를 다음 기준으로 문서에 배치한다.
   - **확정 요구** — 사용자가 요청했거나 이미 승인한 동작, 근거로 확인한 기존 계약 중 보존해야 할 동작.
   - **현재 동작** — 코드나 실행 결과로 확인한 사실. 요청과 다르면 변경 대상으로 드러낸다.
   - **가정** — 예시 데이터처럼 문서 작성에만 쓰이고 제품 동작이나 수용 기준을 바꾸지 않는 해석. 적용 범위와 근거를 적는다.
   - **미결 결정** — 선택에 따라 제품 동작, 범위, 권한, 데이터 처리, 외부 계약이나 수용 기준이 달라지는 문제. 요청자 확인 원칙에 따라 질문한다.

## 요구사항과 수용 기준 작성

1. 범위를 먼저 정한다. 누가 또는 무엇이, 어떤 조건에서, 어떤 작업을 할 수 있어야 하고, 그 결과 무엇이 달라지는지 적는다. 요청에서 직접 달라지는 동작과 관련된 보존 조건을 각각 명시한다.
2. 독립적으로 검토할 수 있는 요구에 `REQ-01`, 수용 기준에 `AC-01` 형식의 고유 ID를 붙인다. 확정 요구에는 검증할 수 있는 수용 기준을 하나 이상 연결한다.
3. 각 수용 기준에 **사전 조건 → 동작 → 관찰 가능한 기대 결과**를 적는다. 관찰 지점은 화면 표시, API 응답, 조회 가능한 데이터, 파일 존재 여부처럼 실제로 확인할 수 있는 곳을 사용한다. 특정 함수나 라이브러리 사용은 사용자가 그것을 제약으로 지정한 경우에 적는다.
4. 결과가 갈리는 경우를 확인한다. 수치나 날짜 기준이면 비교 방향, 기준 시점, 경계 포함 여부를 명시하고 경계의 양쪽을 다룬다. 상태·권한·데이터 참조나 재실행에 따라 결과가 달라지는 경우도 각각 검토한다. 기대값이 미결인 경우 관련 요구나 수용 기준 ID를 미결 결정에 연결하고 조건부로 표시한다.
5. 대상이 되는 시점과 작업을 실행하는 시점을 구분한다. 자동 실행, 운영 기한, 장애 복구 보장처럼 추가 약속이 생기는 항목은 요청이나 기존 계약에서 근거를 찾는다. 근거가 없으면 구현 판단에 필요한 항목만 미결로 남긴다.

문서 양식이 없거나 조건과 기대 결과를 나누기 어려우면 [요구사항 문서 구조와 작성 예시](references/requirements-document.md)를 읽는다.

## 문서 갱신과 반환

기존 문서를 갱신할 때는 새 정보가 어떤 요구사항과 수용 기준에 영향을 주는지 확인한다. 확인된 누락이나 충돌은 문서 본문에 반영한다. 기존 기준의 의미가 그대로면 ID를 유지하고, 의미를 바꾸거나 기준을 나누면 관련 연결도 갱신한다. 사용자 결정이 필요한 항목은 미결로 남긴다.

전달 전에 다음을 확인한다.

- 확정 요구의 근거를 찾을 수 있고, 범위가 사용자 요청과 일치한다.
- 각각의 수용 기준에 빠진 조건이나 서로 충돌하는 기대값이 없으며, 확정 요구마다 관찰 가능한 기준이 연결되어 있다.
- 미결 항목마다 요청자에게 물을 질문과 영향을 받는 기준이 연결되어 있다.

문서 경로가 지정된 경우 그 경로에 Markdown으로 저장하고, 경로가 없으면 문서 본문을 반환한다. 사용자 결정이 필요하면 선택에 따라 달라지는 결과를 담은 질문을 함께 전달한다.
